# Bootloader / Bootstrap — Design Docs

Living design documentation for the Midnight Sun XVI CAN bootloader. These are
planning docs, not a spec — they capture the current state, the known problems,
and where we want to take the design.

> **North-star goal:** the bootstrap+bootloader should become a **drop-in git
> submodule** that any future repo (drive inverter, MPPT, a new board) can add and
> bring up on a new STM32 by editing **one file** (`bootloader_user_config.h`) and
> implementing a small, well-defined port layer. Every design decision below is
> weighed against that goal.

## Decisions locked so far

- **Drop-in git submodule `ms-bootloader`** (one module; everything named `bl_`/`Bl*`,
  the old `Fota*` renamed). The bootstrap+bootloader core + transports + autogen live in
  the submodule; the host repo provides only `bootloader_user_config.h` and a raw-HAL
  port impl — it never re-implements a transport.
- **Layout:** `common/` (shared lib: crc, jump, config, port.h) + `bootloader/`
  (datagram, dfu, state machine) + `bootstrap/` + `transport/{can,uart}` + `port/`.
  Bootstrap & bootloader are two apps linking different subsets of small libs, so
  bootstrap stays ~8 KB (links `common/` only). The HAL seam is `port/` (`bl_port_*`).
- **One user-facing file: `bootloader_user_config.h`.** Flash geometry + CAN (bitrate,
  IDs) + node-id. Timeouts are hardcoded in core (not knobs).
- **Autogenerated linker scripts.** A script reads `bootloader_user_config.h` and
  emits the `.ld`, so the C side and the linker can never drift.
- **Single application region** (no A/B active/staging). Rollback isn't worth 2×
  flash, and the largest app (steering, ~421 KB) cannot fit twice on a 512 KB part.
- **Keep a tiny bootstrap** as a permanent, SWD-only first stage so the bootloader
  can (in v2) be field-updated over CAN with a guaranteed fallback.
- **`BootConfig` = exactly one page** (not a filesystem, no A/B). A flat, CRC'd struct
  holding CRC32s for the bootloader and the app, checked before each jump; **designed
  to grow** (prologue + append-only body + size-delimited CRC) for v2.
- **No MPU/WRP locking** in v1 — the permanent, SWD-reflashable bootstrap is the
  safety net.
- **Consolidate FOTA + CAN bootloader into one module.** Adopt FOTA's layered
  architecture as the base and make the CAN bootloader a **transport**. Shared
  currency is the datagram; transports differ only in fragment/reassemble. Transports
  are submodule code calling the host's raw-HAL `bl_port_*`.
